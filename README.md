# 외자부품 Invoice 엑셀 자동 변환 (Foreign Parts DB)

**기획** 권도연 · HD 생성형 AI 업무자동화 전문가과정 1차수 (Day05 프로젝트 16)
**주소** <https://aebonlee.github.io/hd-project16/>

해외 공급사에서 오는 Invoice(전자 PDF · 스캔본)에서 부품 명세를 뽑아
ERP 업로드용 엑셀 한 장으로 합칩니다.

---

## 핵심 생각 — 계산이 맞는지로 읽은 것이 맞는지 판단한다

공급사마다 양식이 다릅니다. 열 순서도 다르고 이름도 다릅니다.

```
A사: Part No | Description | Qty  | Unit Price | Amount
B사: Pos     | Artikel     | Preis| Menge      | Betrag     ← 단가가 수량보다 앞
C사: 번호    | 품명        | 수량 | 단가       | 금액
```

열 이름으로 맞히려 들면 못 보던 양식에서 통째로 틀립니다.
그런데 Invoice 에는 **반드시 성립하는 식**이 하나 있습니다.

> **수량 × 단가 = 금액**

그래서 한 줄에서 숫자를 전부 뽑아 **어느 조합이 이 식을 만족하는지** 찾습니다.
맞아떨어지면 그 조합이 수량·단가·금액입니다. **열 순서를 몰라도 됩니다.**

이 방식이 덤으로 해결하는 것 두 가지.

**① 유럽식 소수점.** `1.234,56` 은 독일에서 1234.56 입니다.
미국식으로 읽으면 1.234 가 되어 **천 배가 틀리는데**, 화면에는 그냥 숫자로 보여
알아채기 어렵습니다. 두 방식으로 다 읽어 보고 계산이 맞는 쪽을 고릅니다.

**② 문자인식 오류.** 스캔본에서 8 을 3 으로 읽는 일이 흔합니다.
계산이 어긋나면 그 줄이 바로 드러납니다.

### 곱셈만으로는 못 가리는 것 — 표 전체를 본다

`2.480,00 × 2 = 4.960,00` 은 **수량 2 · 단가 2480** 으로도,
**수량 2480 · 단가 2** 로도 아귀가 맞습니다. 검산으로는 절대 못 가립니다.
실제로 개발 중에 여기서 수량과 단가가 뒤바뀌었습니다.

그런데 같은 표의 다른 줄(`1.234,56 × 10 = 12.345,60`)은
수량이 정수여야 한다는 조건에서 자리가 확정됩니다.
**표는 열이 일정하므로 그 자리를 표 전체에 적용**하면 애매한 줄도 풀립니다.
자리는 뒤에서부터 셉니다 — 품번에 숫자가 섞여 있어(`DIN-912-M8`) 앞에서 세면 어긋납니다.

## 이중 엔진

| 파일 | 어떻게 | 정확도 |
|---|---|---|
| 전자 PDF | 글자를 그대로 꺼냅니다 | 높음 |
| 스캔본 PDF | 2배 해상도로 그린 뒤 문자인식 | **낮음 — 검산 필수** |
| 사진 (JPG·PNG) | 문자인식 | **낮음** |
| 엑셀 · CSV | 표를 그대로 | 높음 |

전자냐 스캔이냐는 **자동 판단**합니다(쪽당 글자 수가 60자 미만이면 스캔본).
전자 PDF인데 글자가 깨져 나오면 화면에서 **스캔본으로 강제**를 켜세요.

**어느 엔진으로 읽었는지 화면과 엑셀 양쪽에 남깁니다.**
문자인식으로 읽은 값은 신뢰도가 다른데, 안 적으면 사람이 어디를 더 봐야 할지 모릅니다.

## 모르는 것을 지어내지 않습니다

| 상황 | 흔한 처리 | 여기서는 |
|---|---|---|
| 계산이 안 맞는 줄 | 버리거나 억지로 넣음 | **자리로 짐작해 넣고 “짐작” 표시** — 버리면 부품이 통째로 빠진 채 엑셀이 만들어지고 아무도 모릅니다 |
| `03/04/2026` | 미국식으로 단정 | **애매하다고 표시** — 3월 4일인지 4월 3일인지 나라마다 다릅니다 |
| 공급사 라벨이 없음 | 아무 줄이나 씀 | 맨 위 회사명을 쓰되 **추정했다고 남김** |
| 합계·운임 줄 | 부품으로 섞임 | 걸러 내고 **몇 줄 건너뛰었는지 알림** |
| 주소·전화번호 | 숫자가 셋이라 부품이 됨 | 앞에 글자가 없거나 숫자가 붙어 있으면 제외 |

## 검증·수정 화면이 가장 중요합니다

> **자동으로 읽은 값을 안 보고 그대로 ERP 에 올리지 마세요.**
> 손으로 칠 때는 한 건 틀리지만, 잘못 읽은 규칙은 **백 줄을 한꺼번에** 틀리게 만듭니다.

- 표의 칸을 눌러 **바로 고칠 수 있습니다.**
- **수량이나 단가를 고치면 금액이 자동 재계산**됩니다.
- **금액을 직접 고치면 그대로 둡니다** — 원본 금액이 맞고 단가가 반올림된 경우가 있습니다.
- 헤더 열(파일·Invoice No·날짜·Supplier·통화)은 **기본으로 접혀 있습니다.**
  줄마다 똑같이 반복되는데 켜 두면 정작 봐야 할 **검산 열이 화면 밖으로 밀립니다.**

가장 빠른 확인법은 **문서 카드의 합계를 원본 Invoice 의 Sub Total 과 맞춰 보는 것**입니다.
여기가 다르면 부품이 빠졌거나 잘못 읽은 것입니다.

## 엑셀 — 평평한 표

부품 한 줄마다 헤더를 **통째로 붙입니다.** 헤더를 위쪽에 한 번만 두면
여러 Invoice 를 합쳤을 때 어느 줄이 어느 것인지 알 수 없습니다.

```
파일명 · 읽은방식 · InvoiceNo · 날짜 · Supplier · 통화 · PONo
       · PartNo · Description · Qty · UnitPrice · Amount
       · 검산 · 비고 · 짐작 · 수정됨 · 읽은줄
```

`읽은줄` 은 원문 그대로입니다. **틀렸을 때 어디서 왔는지 봐야 하기 때문**입니다.

## 폐쇄망에서 돌아갑니다

바깥을 부르는 곳이 **한 군데도 없습니다.** 파일이 서버로 나가지 않습니다.

- PDF 읽기 — `lib/pdf.min.mjs` + `lib/cmaps/` (한글 PDF 에 cMap 이 필요합니다)
- 문자인식 — `lib/tesseract.min.js` + `lib/core/` + `lib/tessdata/` (영문)
- 엑셀 — `lib/xlsx.full.min.js`

라이브러리가 15MB 로 큽니다. 문자인식 엔진과 언어 데이터 때문인데,
이걸 빼면 스캔본을 아예 못 읽으므로 줄일 수 없습니다.

```sh
node test/logic.test.js     # 91개
node test/smoke.browser.js  # 브라우저에 실제로 띄운다 (29개)
```

CI(`.github/workflows/test.yml`)에서 자동으로 돕니다. 여기에 **동봉 라이브러리가
다 있는지** 세는 단계가 하나 더 있습니다 — `lib/` 중 하나가 빠져도 단위 테스트
91개는 전부 통과하기 때문입니다(순수 함수는 `lib` 를 안 씁니다).

왜 이렇게 만들었는지는 [`docs/개발일지.md`](docs/개발일지.md), 작업 규칙은
[`CLAUDE.md`](CLAUDE.md) 에 있습니다.

| 파일 | |
|---|---|
| `js/invoice.js` | 숫자 읽기 · 줄 맞히기 · 헤더 · 평탄화 (순수 함수) |
| `js/read.js` | 전자 PDF / 문자인식 / 엑셀 읽기 |
| `js/app.js` | 화면 |

검사기를 만든 뒤 **일부러 열 가지를 깨뜨려** 전부 잡히는 것을 확인했습니다.
그중 두 가지는 실제 결함이었습니다.

- `12.50` 을 유럽식 천단위(1250)로도 읽어 **검산이 통째로 무력해졌다** —
  `5 × 1250 = 6250` 도 성립해 두 해석이 서로 아귀가 맞았습니다.
  천단위는 반드시 세 자리씩 끊는다는 규칙으로 갈랐습니다.
- 라벨을 찾을 때 줄을 바깥 고리로 돌아 `COMMERCIAL INVOICE` 제목이
  느슨한 `invoice` 에 먼저 걸렸고, **Invoice No 가 "Invoice" 라는 글자**로 나왔습니다.

## 남은 것 — 실물 샘플이 필요합니다

기획서에 “첨부 PDF에 형광펜으로 추출 대상 필드를 표시해 둠”이라 적혀 있는데
**그 파일을 받지 못했습니다.**

지금은 양식에 기대지 않는 방식이라 대부분의 Invoice 를 읽지만,
실제 공급사 양식으로 맞춰 보지 않았습니다. 특히 이런 것이 남습니다.

- **여러 줄에 걸친 품명** — 둘째 줄이 따로 떨어져 나옵니다
- **한 줄에 수량·단가·금액이 흩어진 양식** — 지금은 한 줄 안에 있어야 찾습니다
- **공급사별 파싱 규칙(템플릿) 저장** — 실물을 보고 나서 만드는 편이 맞습니다

샘플 PDF 를 받으면 곧바로 맞추겠습니다.
그전까지는 **문서 카드의 합계를 원본과 대조**하는 것으로 확인하세요.
